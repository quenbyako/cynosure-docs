# Конфиденциальность и безопасность

Обеспечение защиты данных и безопасного взаимодействия с внешними сервисами является приоритетом архитектуры Cynosure. Ниже приведены основные принципы обработки и хранения информации в системе.

## Обработка персональных данных

Для функционирования системы используются только те данные, которые необходимы для идентификации сессии и предоставления сервиса:

- **Идентификатор Telegram**: используется для привязки аккаунта и хранения индивидуальных настроек.
- **История сообщений**: сохраняется внутри конкретных тредов для поддержания контекста диалога. Информация **не** используется для обучения моделей и доступна только в рамках сессий конкретного пользователя.
- **Метаданные**: система фиксирует техническую информацию о запросах (время, объем затраченных токенов, использованные инструменты) для контроля лимитов и диагностики ошибок.

## Безопасность интеграций (OAuth и MCP)

При подключении внешних инструментов (серверов MCP) действуют следующие защитные механизмы:

1. **Шифрование токенов**: все ключи доступа и токены авторизации (OAuth), полученные от сторонних сервисов (Notion, Google и др.), хранятся в зашифрованном виде.
2. **Сессионный доступ**: агент получает доступ к инструментам только после явного подтверждения авторизации пользователем через официальный интерфейс стороннего сервиса.
3. **Изоляция инструментов**: инструменты, подключенные в одном аккаунте, недоступны другим пользователям системы. Каждый агент работает строго с тем набором прав, который предоставлен владельцем аккаунта.

## Прозрачность и контроль

Система предоставляет полную видимость действий ИИ:

- Каждый вызов внешнего инструмента отображается в чате в режиме реального времени.
- Пользователь имеет возможность в любой момент прекратить использование инструмента, удалив соответствующий тред или отозвав права доступа на стороне стороннего сервиса.

## Взаимодействие с разработчиками

Для отладки системы и решения технических проблем используются логи, привязанные к Trace ID. Данные в логах содержат технические параметры запроса и сообщения об ошибках. Содержимое приватных диалогов **не попадает** в технические логи, если это не связано напрямую с критическим сбоем обработки сообщения.
